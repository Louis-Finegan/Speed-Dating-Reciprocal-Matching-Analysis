# Theoretical setup and definitions

This document explains the current implementation in [run_analysis.py](../scripts/run_analysis.py) and provides context for [the results discussion](results_discussion.md). It also defines maximum-weight matching and stable matching, which are planned extensions and are **not implemented in the current results**.

## 1. Participants, events and encounters

For each speed-dating event (wave) $w$, let $A_w$ and $B_w$ denote the two participant groups. In the current code, group A contains participants coded `gender=1` and group B contains participants coded `gender=0`. These groups reflect the dataset's event format, rather than a general model of gender or relationship preferences.

Let

$$
E_w \subseteq A_w \times B_w
$$

be the set of eligible recorded encounters. The current evaluation retains pairs with records in both directions after filtering. It does not construct unobserved encounters.

A directed row $(w,i,j)$ describes participant $i$'s encounter with participant $j$. The reverse row $(w,j,i)$ describes the same encounter from the other participant's perspective. These are related observations, not independent encounters.

The current code uses group A as the initiating side for recommendations. Exposure metrics therefore concern group B.

## 2. Directional attraction and observed mutual interest

Define the directional decision

$$
Y_{ij} =
\begin{cases}
1 & \text{if participant } i \text{ expresses interest in seeing } j \text{ again},\\
0 & \text{otherwise}.
\end{cases}
$$

In a directed dataset row, `dec` records $Y_{ij}$ and `dec_o` records the other participant's decision $Y_{ji}$.

The theoretical mutual-interest outcome is

$$
M_{ij}=Y_{ij}Y_{ji}.
$$

Thus mutual interest requires both participants to say yes. This is an interest-in-another-date outcome, not evidence of long-term compatibility.

The implementation evaluates the supplied `match` column as the observed mutual outcome. Consistency between `match`, `dec`, `dec_o` and reverse records still needs explicit validation; the equation above specifies the intended definition.

## 3. Predicting directional attraction

For a directed encounter, let $X_{ij}$ contain the current predictors:

| Code variable | Meaning in the model |
|---|---|
| `age` | Initiating participant's age |
| `age_o` | Partner's age |
| `samerace` | Dataset indicator of shared racial category |
| `int_corr` | Dataset measure of interest correlation |
| `goal` | Initiating participant's coded relationship goal |

These features are intended to be available before the decision. Their questionnaire timing and construction require a documented audit before making a formal claim that they are free of feature leakage.

The target probability is

$$
p_{ij}=P(Y_{ij}=1\mid X_{ij}).
$$

The current logistic regression estimates

$$
\widehat p_{ij}
=\sigma\!\left(\widehat\beta_0+
\widehat\beta^{\mathsf T}\widetilde X_{ij}\right),
\qquad
\sigma(z)=\frac{1}{1+e^{-z}},
$$

where $\widetilde X_{ij}$ denotes median-imputed, standardized predictors, together with missingness indicators generated by the pipeline. Preprocessing and the model are fitted on training data. A single shared model predicts both directions.

The current implementation treats `goal` as a numeric predictor, imposing an ordered, linear effect on log odds. A categorical encoding is a planned methodological improvement.

## 4. Reciprocal probability score

The probability of mutual interest is a joint probability:

$$
q_{ij}=P(Y_{ij}=1,Y_{ji}=1\mid X_{ij},X_{ji}).
$$

The code approximates it using

$$
\widehat q_{ij}=\widehat p_{ij}\widehat p_{ji}.
$$

Interpreting this product as a mutual-interest probability requires conditional independence of the two decisions given the available information, and adequate directional probability estimates. Shared chemistry or unmeasured encounter characteristics can violate this assumption. Calibration of directional predictions alone does not guarantee calibration of their product.

For example, directional estimates of 0.8 and 0.3 give a reciprocal score of 0.24. This is a model estimate, not an observed outcome or a guaranteed 24% success rate.

## 5. Recommendations and capacity

Let $x_{ij}\in\{0,1\}$ indicate whether encounter $(i,j)$ is selected as a recommendation. Only edges in $E_w$ may be selected.

Each initiating participant has a recommendation budget $k$:

$$
\sum_{j:(i,j)\in E_w}x_{ij}\leq k.
$$

Recommendations do not by themselves form a one-to-one matching: several participants may be recommended to the same person, and an initiator may receive several candidates.

### Random recommendations

For each initiator, the code samples up to $k$ candidates without replacement by randomly permuting their eligible encounters. There is no recipient capacity. The saved result represents one random draw.

### Reciprocal ranking

For each initiator, the code selects up to $k$ candidates with the largest $\widehat q_{ij}$. This maximizes that initiator's sum of reciprocal scores when there are no recipient constraints. Multiple initiators can select the same recipients.

### Capacity-constrained reciprocal ranking

The current heuristic additionally imposes

$$
\sum_{i:(i,j)\in E_w}x_{ij}\leq k
$$

for every recipient. It processes initiators in sorted event/identifier order and greedily takes their highest-scoring candidates with remaining capacity.

The allocation depends on processing order. It need not maximize total score or the number of recommendations. A recipient cap can therefore improve exposure equality while leaving some initiating budgets unfilled.

## 6. Metrics used in the saved results

Let $S$ be all selected edges across held-out events and let $N=|S|$.

### Recommendation count

$$
N=\sum_{(i,j)\in E}x_{ij}.
$$

This measures recommendation volume. Methods with different counts should be compared using both success rates and total yield.

### Observed mutual-interest rate

$$
H=\frac{\sum_{(i,j)\in E}x_{ij}M_{ij}}{N},
\qquad N>0.
$$

The CSV calls this `reciprocal_hit_rate`. It is the fraction of selected encounters that have recorded mutual interest. The numerator

$$
T=\sum_{(i,j)\in E}x_{ij}M_{ij}=NH
$$

is the total number of mutual-positive encounters selected. It counts edges, not unique participants or exclusive couples. An individual may contribute to several selected edges.

The reported rate pools selected edges across events; events with more selected edges receive greater weight. It is not an equally weighted average of event rates.

### Recipient exposure and coverage

For recipient $j$, define exposure as

$$
e_j=\sum_i x_{ij}.
$$

Exposure means the number of selected recommendation edges pointing to the recipient. It does not mean an actual profile view or message.

Let $B$ contain all distinct eligible event–recipient pairs in the held-out candidate graph, including those receiving zero exposure. With $m=|B|$, recipient coverage is

$$
C_B=\frac{1}{m}\sum_{j\in B}\mathbf 1(e_j>0).
$$

Coverage of 100% means every eligible recipient receives at least one recommendation. It does not establish coverage of all dataset participants, filled initiator budgets or equal exposure counts.

### Exposure Gini

The implemented Gini coefficient is

$$
G=\frac{\sum_{a=1}^{m}\sum_{b=1}^{m}|e_a-e_b|}
{2m\sum_{a=1}^{m}e_a}.
$$

For nonzero total exposure, zero indicates equal exposure. Larger values indicate greater concentration. Zero-exposure recipients are included. For a finite population of size $m$, the maximum is $(m-1)/m$.

The code returns zero for an empty population or zero total exposure as a computational convention. Such a value should not be interpreted as successful allocation.

Gini measures exposure inequality only; it does not establish fairness across demographic groups, preference satisfaction or welfare.

## 7. Prediction metrics printed in the terminal

The same metrics are calculated for directional decisions and for mutual outcomes, using their respective probability estimates.

| Metric | Interpretation |
|---|---|
| Average precision (AP) | Summarizes precision as recall increases through the score ranking; higher is better, and interpretation depends on positive-outcome prevalence |
| ROC AUC | Measures ranking discrimination between positive and negative cases, with half credit for ties; 0.5 corresponds to chance ranking |
| Brier score | Mean squared probability error, $n^{-1}\sum_r(\widehat p_r-y_r)^2$; lower is better |

Predictive accuracy and allocation performance answer different questions. A model may rank individuals well while its recommendations concentrate exposure. Brier scores should be compared against an appropriate constant-probability baseline, and probability calibration should be inspected separately.

## 8. Planned maximum-weight bipartite matching

For a one-to-one comparison, use constraints

$$
\sum_jx_{ij}\leq1,\qquad \sum_ix_{ij}\leq1.
$$

Maximum-weight matching solves

$$
\max_x\sum_{(i,j)\in E_w}\widehat q_{ij}x_{ij}
$$

subject to those constraints. It chooses an allocation globally, rather than processing initiators greedily. With capacities larger than one, the corresponding formulation is a capacitated bipartite matching problem.

If the scores are valid marginal mutual probabilities, the objective is the expected number of mutual-positive selected edges. Linearity of expectation justifies this sum without requiring independence between different edges. The product approximation for each individual edge remains a separate assumption.

Maximizing predicted yield does not guarantee maximum observed yield, equal exposure or stability. A comparison with top-$k$ recommendations must use compatible capacities and candidate sets.

## 9. Planned Gale–Shapley stable matching

A one-to-one matching $\mu$ assigns each participant at most one partner. Each participant has an ordered preference list over acceptable candidates; being unmatched must also have a specified interpretation.

A blocking pair is an acceptable edge $(i,j)$ not in the matching such that both participants prefer each other to their current assignments, treating being unmatched according to the stated preference convention. A matching is stable if it contains no blocking pair.

One proposed preference construction ranks candidates for $i$ by $\widehat p_{ij}$, and candidates for $j$ by $\widehat p_{ji}$. These are estimated preferences. The observed binary decisions do not provide complete rankings.

Gale–Shapley deferred acceptance produces a stable matching for strict preference lists under the standard one-to-one setup. The implementation must define acceptable edges, resolve ties consistently and specify which side proposes. Proposer choice can change the result.

Stability concerns incentives under the supplied preferences. It does not imply maximum mutual probability, demographic fairness or stability under participants' unknown true preferences.

## 10. Evaluation assumptions and interpretation

The code holds out entire waves using a fixed random seed and trains on the remaining waves. This keeps both directions of an encounter within the same split. Participant overlap across waves still needs to be checked before claiming participant-disjoint evaluation.

There is currently no separate validation set, grouped model-selection procedure or uncertainty interval. The random recommendation baseline also uses only one seed. A stronger comparison should repeat random allocations and estimate uncertainty using events as sampling units, preserving paired comparisons between methods.

The current results distinguish three types of quantity:

| Type | Examples |
|---|---|
| Observed | Recorded `dec`, `dec_o` and `match` labels |
| Predicted | Directional probabilities and reciprocal product scores |
| Simulated allocation | Recommendation edges selected by a policy during offline replay |

Observed labels exist because participants encountered one another in the study. Reusing those labels to evaluate a selected subset does not establish that a recommendation policy would cause the same outcomes in a new platform setting.

The preliminary table therefore supports discussion of **selection yield and exposure distribution within recorded encounters**. Claims about reliable improvements, optimal matching, stability or real-world causal effects require further implementation and evaluation.
